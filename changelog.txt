== Changelog ==

Every change to SEO Pro Stack. readme.txt lists the latest version in short.

= Unreleased =
* Change: all Kadence and Fluent/WPManageNinja vendor links use the supplied referral IDs, keeping product paths and pricing anchors. Kadence bundles link directly to Liquid Web; Scalability Pro uses its current Super Speedy Plugins product page and pricing section.
* New: 11 missing WPManageNinja free plugins and add-ons, plus FluentAffiliate Pro, FluentPlayer Pro, Paymattic Pro and AzonPress in Pro Plugins. Matching free cards and All rows use the referral links for Go Pro. FluentAuth stays free only; AzonPress has no listed WordPress.org free version.
* Fix: Fixes for other plugins makes the "settings page" link in Search Console's dashboard box (3.1.3) open its settings; it went to a page the plugin no longer has, which WordPress refused.
* New: Search Console (Tropicalista), which shows Google Search Console data in wp-admin, is in the recommended free plugins (SEO).

= 0.11.8 =
* Fix: Load plugins only where needed loads a base plugin and its Pro or Premium add-on together on every screen, or skips both (FluentBooking, Fluent Boards, Fluent Support, Fluent Forms, FluentCRM). Before, a screen could skip the base while its Pro add-on loaded, so the add-on showed its "requires the base plugin" notice there, or load the base without the add-on, leaving out the add-on's features. Add-ons are also matched by name (FluentCRM Pro, Fluent Forms Pro Add On Pack). Screens are learned again once.

= 0.11.7 =
* New: Tidy WooCommerce admin can remove the payment plugins WooCommerce suggests under "More payment options" on Settings → Payments (ticked by default for sites that have not chosen items yet), replacing Disable Bloat's "Hide payment providers". Disable Bloat's "Remove resource hints" needs nothing in its place: WordPress 7.1 no longer adds the s.w.org DNS prefetch it removed.
* Fix: Fixes for other plugins stops Tutor LMS Pro 4.1.0 adding PHP warnings to the debug log on every update check when its update reply has no details (as with copies from GPL resellers).
* Fix: Load plugins only where needed loads paid add-ons named after an active plugin, such as fluent-booking-pro, wherever that plugin loads.

= 0.11.6 =
* New, off by default: Rank Math defaults fills empty focus keywords from titles for chosen post types, warns when more than 20% of published posts are pillars and offers selected-post pillar removal.
* New: Tools → Old addresses has Remove all (it asks first), and ticking the whole page offers Select all to take in every page, as Select all across pages does in post lists. Before, only the 50 old addresses on screen could be removed at once, so a site with a thousand needed twenty-one rounds. The box above the list also ticks the page where another plugin's script stops WordPress's own from doing it.
* Fix: deactivating Freesoul Deactivate Plugins or its PRO add-on left the other one active and, on networks or when Freesoul's own code did not run, its must-use file behind, still skipping plugins on single sites. Fixes for other plugins now deactivates both together and deletes the file once neither is active anywhere, also when the Plugins screen finds one left from before.
* Fix: Readabler stopped the Plugins screen with a critical error whenever its product information request failed (a timeout, or HTTP Requests Manager blocking it), and made that request on every load of the screen. Fixes for other plugins skips the request while Readabler's cached answer is there and removes the notice that throws.

= 0.11.5 =
* New: Hosting needs warns about configured but unreachable object caches, recommends unused local Redis or Memcached even on small sites, and names the cache in site facts. Checks run at most daily, never on visitor requests, without changing cache settings.
* New, off by default: External link icons (Links tab), following link colours and Kadence light/dark switching without scripts or extra asset requests. Related-domain and per-link bypasses; image links and buttons stay plain. Only Link Whisper's icon is covered, not its linking tools.
* Fix: Updates from GitHub could not update from private repositories on sites where HTTP Requests Manager blocks requests (its "smart" or other blocking modes): it makes every request follow redirects, so GitHub's download address was lost. Its requests to GitHub now never follow redirects, so the token also stays with GitHub. On such sites, install this version once by hand; later updates arrive by themselves.
* Fix: Load plugins only where needed did nothing on sites updated to 0.11.3 or 0.11.4: every plugin went into Always load these plugins, and the site's first learn put every plugin it skips automatically into Always load these plugins on the site. Sites stored their old lists empty, which was taken as a choice. Both lists are cleared where that happened; lists with real choices are kept.
* Fix: the Theme tab showed a broken Kadence screenshot on sites that block images from other sites (a host or security plugin's Content Security Policy, or a browser blocker). An installed Kadence now shows its own screenshot from the site; when it cannot load, the panel stays plain instead of showing a broken image.
* Fix: on sites with Freesoul Deactivate Plugins, a replaced plugin's Deactivate link (such as "Deactivate Disable Bloat PRO" under Remove WordPress extras) reloaded the page but left the plugin active, and Activate and Deactivate on the Plugins tab said they worked but did not. Freesoul saves its own copy of the active plugins list over any change not made from the Plugins screen. SEO Pro Stack now checks the change was saved and, if not, saves just that change.
* Change: Load plugins only where needed now skips, for visitors (who have no admin bar), plugins that only add to the admin bar, and Learn which plugins each page needs is on by default (also on sites where the feature is still off), so switching the feature on gives the full speed-up straight away.

= 0.11.0 =
* Change: in Free Plugins, Advanced Database Cleaner, Anti-Malware Security and Brute-Force Firewall, Debug Log Manager, Query Monitor, User Switching and WP Crontrol say they are not needed day to day: deactivate or delete them so the site runs at full speed, and turn them on only to look into a problem or for admin work.
* Change: Updates from GitHub now uses a shared updater that other wpallstars plugins can carry too. Only the newest copy on the site runs, so all of them are checked together, once. Private repositories can use one WPALLSTARS_GITHUB_TOKEN in wp-config.php for every plugin; SEOPROSTACK_GITHUB_TOKEN and the seoprostack_github_* filters still work.
* Change: Free Plugins lists WP-Optimize again on LiteSpeed servers, with a note that the site does not need it there; on other servers its note says it is for its page cache. The WP-Optimize preset turns that page cache on, on servers other than LiteSpeed, through WP-Optimize's own save code, so Reset and Undo turn it off and back on cleanly.
* Change: the WooCommerce preset turns on Deferred emails, so checkout does not wait for the mail server. Emails go out through Action Scheduler, which needs WP-Cron or a server cron. If emails arrive late or not at all, check WooCommerce → Status → Scheduled Actions (group woocommerce-emails) for pending or failed woocommerce_send_queued_transactional_email actions, and turn Deferred emails off in WooCommerce → Settings → Advanced → Features. Reset and Undo still work.
* Fix: WebP and AVIF images now use the quality you set; before, WordPress's own quality was used whatever the setting said. Changing a quality converts the pictures again in the background, and copies from earlier versions are made again once.
* New: WebP and AVIF images: Quality by picture size (on), sharper thumbnails and smaller large pictures.
* Change: WebP and AVIF images makes sharper copies by default: WebP quality 90 and AVIF 70, instead of 80 and 60. Sites that saved their own quality keep it.
* New: WebP and AVIF images checks that browsers get the copies, and says what to do when they do not, such as restarting LiteSpeed so it reads the new rules.
* New: Watermark pictures can mark, mark again or unmark the whole Media Library in the background from its settings, with progress and a Stop button. Bulk actions carry on in the background instead of leaving pictures out. In the Media Library's tile view, a picture's details now have Add or Remove watermark.
* Fix: background picture work no longer runs past the server's time limit when several jobs run together, and no longer stops before it starts on servers that have run for a long time (watermark bulk actions seemed to do nothing).
* New, off by default: Restrict content shows posts, pages, categories and blocks only to logged-in people, logged-out visitors or chosen roles. Choose “Who sees this” in the editor, on a category or tag, or in a block’s Visibility panel. Others see what is above the More block, or the excerpt, and a message with a login link, also in lists, feeds and the REST API. A Members only block keeps part of a public post for members. Shop products can be kept for members too: WooCommerce hides their price and details, and neither WooCommerce nor FluentCart lets others buy them. Membership, payment and sign-up plugins give people a role, and the role decides what they see. Replaces Content Control, now closed on WordPress.org: its block rules and [content_control] shortcode keep working, and its restrictions for chosen posts and categories carry over.
