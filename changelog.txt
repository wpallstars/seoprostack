== Changelog ==

Every change to SEO Pro Stack. readme.txt lists the latest version in short.

= Unreleased =
* Fix: Fixes for other plugins sets LiteSpeed's noabort variable for every request, not just WordPress cron and Action Scheduler. Visitors leaving pages no longer interrupt queries and leave "Commands out of sync" errors at shutdown. Requests keep PHP's and LiteSpeed's normal time limits; abandoned requests still use CPU, reduced for anonymous pages served by LiteSpeed Cache's page cache. Existing marked .htaccess blocks update on the next main-site admin request; the main site's switch still controls the shared network file, and switching off or deactivating still removes the block (GitHub issue #967).
* Fix: Media in cloud storage resumes adopt and migrate batches from separate, non-autoloaded destination-bound cursors saved under the existing lease. Commands report the next position and clear their cursor at inventory end to revisit deferred or failed records on the next pass. --from-start ignores the cursor; dry runs and explicit --attachment runs never change it. Existing verification, budget and compare-and-swap behavior is unchanged (GitHub issue #965).

= 1.3.86 =
* Fix: Email protection also hides the address in a `mailto:` link's other attributes. The block editor's link control writes `data-id="mailto:…"`, and a `title` or `aria-label` may repeat the address, so 1.3.85 still showed it in the HTML. On an email link, every attribute other than `href` whose value holds an address or `mailto:` is removed; `title`, `aria-label`, `aria-description` and `data-*` ones are XOR-encoded together as JSON in `data-sps-attrs`, and `assets/js/email-protection.js` restores only those names, never event handlers or styles. Any other such attribute is dropped (GitHub issue #959).

= 1.3.85 =
* New, on by default: Email protection (`SEOProStack_Email_Protection`, Security tab, `email_protection`). Email addresses in text and `mailto:` links rendered through `the_content`, `widget_text`, `widget_text_content`, `widget_block_content`, `render_block` and `wp_nav_menu_items` become placeholders (`<span class="sps-email" data-sps-e="…">` with a `<noscript>` note, and `href="#sps-email"` with `data-sps-mailto` on links, keeping their classes and inner markup), XOR-encoded with one key per response. `assets/js/email-protection.js`, deferred and enqueued only when a page has a placeholder, restores the text and links. Entity-encoded addresses (such as `antispambot()`'s) are caught too. Comments, `<script>`, `<style>`, `<textarea>`, `<title>`, `<noscript>` and other attributes are left alone, as are the admin, feeds, Ajax, REST and JSON responses and `wp_mail`; stored content does not change. Works without Cloudflare's Email Address Obfuscation (and alongside it); scrapers that run JavaScript can still read addresses. The `seoprostack_email_protection_skip` filter leaves a context plain (GitHub issue #927).
* Fix: Media in cloud storage reserves offloaded filenames and refuses conflicting uploads. The new wp seoprostack media-storage collisions command reports shared paths and keys; --repair renames earlier attachments, copies only local bytes matching the recorded SHA-256, and requeues failed owners once their conflicts are cleared, including across repair pauses. Shared bucket objects stay untouched; missing or mismatched original bytes must be re-added (GitHub issue #956).
* Fix: Kadence Pro dark mode re-declares the four secondary button colour variables on body.color-switch-dark when their Customizer values reference palette slots. Text, hover text and backgrounds resolve against the dark palette instead of the light root; literal colours, transparent and light mode stay unchanged (GitHub issue #942).
* Fix: admin Dark mode: Debug Log Manager's Latest Errors dashboard widget (`#debug_log_manager_widget`) kept its light colours, which it prints in a `<style>` block inside the widget (`get_dashboard_widget_entries()`, 2.5.3), so the stylesheet copies did not reach them: the `#f6f7f7` footer behind Go to Debug Log Manager and odd entries, `#e6e7e7` lines and `#50575e` source links (`#2271b1` on hover). The footer is now the raised surface with muted text, the entries take the stripe and border colours, and the links are muted, with the light accent on hover and focus (`admin/css/seoprostack-whole-theme.css`) (GitHub issue #947).

= 1.3.84 =
* New: Media in cloud storage optionally uploads Watermark pictures' kept originals to SEOPROSTACK_MEDIA_STORAGE_ORIGINALS_BUCKET, a separate private bucket. Signed downloads check size and SHA-256 for unmarking, re-marking and cropping; verified local copies go only with Remove local copies on. CLI counts, explicit restore and durable private-object deletion retries are included. Without the constant, originals stay local (GitHub issue #943).
* Fix: Private-original uploads retry separately from confirmed public media; completed inventories no longer restart, failed inventory jobs retain their cursor, and durable deletion jobs let replaced pictures discard stale watermark records.
* New: Avatars without Gravatar (`SEOProStack_Avatar_Privacy`) has Copy pictures from Gravatar (`avatar_gravatar_import`, on by default at the owner's request): the cron hook `seoprostack_avatar_gravatar_import` takes 20 people at a time who can write posts (`capability__in` `edit_posts`) and are due (user meta `seoprostack_avatar_gravatar` missing, or a retry time now due), downloads their 512px picture from secure.gravatar.com by the SHA-256 hash of their email address, with no default image (404 instead) and the site's avatar rating, and stores it with the profile picture code (marked `gravatar`). A 404 or an unreadable picture records 0 (not asked again until the email address changes, `profile_update`); a failed request or unwritable folder is retried a day later. Pictures uploaded or removed here, and Avatar Privacy's, are never replaced. New people and role changes schedule a batch; switching the setting off unschedules it (GitHub issue #945).
* Fix: Avatars without Gravatar turns `show_avatars` on once in settings version 34 where the feature is on (new installs too): with it off, `get_avatar()` returned false and Kadence's author meta printed an empty avatar box. Version 34 also schedules the first Gravatar copies (GitHub issue #945).
* Fix: Avatars without Gravatar stops Kadence Pro's Local Gravatars (and the Local Gravatars plugin) through their `get_local_gravatars_max_process_time` and `get_local_gravatars_fallback_url` filters, so avatar addresses stay as printed instead of being downloaded again into `wp-content/gravatars/` (a loopback copy of each local file, and a broken address when a download failed). Kadence Pro's setting is not changed (GitHub issue #945).

= 1.3.82 =
* New, on by default: Modal links (`SEOProStack_Modal_Links`, Links tab, `modal_links`). A link to `#id` on the same page, where that element is a modal or drawer (`<dialog>`, `role="dialog"` or `role="alertdialog"`, `aria-modal="true"`, Kadence's `.popup-drawer` or a Kadence Modal block, `.kadence-block-pro-modal`), opens it: the modal's own opener outside it (`[data-toggle-target="#id"]`, `[data-modal-open]`, `[data-micromodal-trigger]` or `[aria-controls]`) is clicked, so Kadence opens `#login-drawer`, `#search-drawer`, `#mobile-drawer` and `#cart-drawer` with its own focus handling and scroll lock; otherwise a Kadence Modal block opens with `MicroModal.show()` and Kadence Blocks Pro's settings (`kt-modal-init.js`), and a `<dialog>` gets a cancelable `seoprostack:open-modal` event, then `showModal()`. Before, Kadence opened its drawers only from its header toggles, and its Modal block only from links with the `modal-trigger` class at page load (`initializeMicroModal()`), so an editor's text link to `#login-drawer` only jumped to a hidden element. The click listener runs in the capture phase, before Kadence's smooth scrolling for same-page anchors would scroll to the hidden element. A page loaded with such a hash opens it after `load`; one already open is left as it is. Other links to IDs (anchors, tabs, accordions, Cookie Consent's `#cookie-settings`), clicks with a modifier key, `download` links and links with another `target` keep their behaviour. Links that open a modal get `aria-haspopup="dialog"` and `aria-controls`. The `seoprostack_modal_links_selectors` filter adds selectors for other kinds of modal (passed as `window.seoprostackModalLinks.selectors`); each is checked when the script starts and one the browser cannot parse is dropped alone, so it cannot stop the built-in selectors matching. Elements matched only by `role="dialog"`, `role="alertdialog"`, `aria-modal="true"` or a filtered selector have no generic way to open, so they open only through their own opener: without one, the click follows the hash as before and a page loaded with it leaves them closed. The script, `assets/modal-links.js`, loads in the footer of front-end pages (GitHub issue #929).
